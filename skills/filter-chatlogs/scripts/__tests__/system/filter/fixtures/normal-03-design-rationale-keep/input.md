---
title: 判定が閾値未満のときファイルをどう扱うか
category: development
---

### User

バッチ判定の結果、DISCARD だけど confidence が閾値未満というケースをどう扱うか決めたいです。いまは KEEP 側に倒しています。案としては (a) そのまま KEEP に倒す、(b) その場で削除する、(c) 判定を確定させずに保留して次回また判定する、の 3 つを考えています。

### Assistant

前提を先に確認させてください。このツールは削除したファイルを復元できますか。それと、同じファイルが次回の実行でも判定対象に残りますか。

### User

復元はできません。削除は不可逆です。判定対象には残ります。キャッシュに結果を書いていて、確定した判定があるファイルは次回スキップします。

### Assistant

(b) は外してください。理由は、閾値未満というのは「モデルが自信を持てなかった」という意味なので、そこで不可逆な削除をすると、判断を誤ったときに取り返しがつかないからです。閾値を設けている意味自体がなくなります。

(a) も勧めません。KEEP としてキャッシュに書いてしまうと確定扱いになり、次回以降スキップされます。つまり「自信がなかった一度の判定」がそのまま永続化されて、二度と見直されません。閾値未満だったという情報が消えるのが問題です。

(c) を勧めます。キャッシュには「未確定」を書き、統計上は skip として数える。次回実行時にもう一度判定されるので、プロンプトを改善したりモデルを変えたりしたときに、その改善が過去の保留分にも効きます。

### User

なるほど、(a) の問題は「KEEP に倒すこと」ではなくて「確定として記録してしまうこと」なんですね。では (c) で確定します。

### Assistant

そのとおりです。判断の分かれ目は KEEP か DISCARD かではなく、確定として記録するかどうかでした。

ひとつ前提を書き留めておいてください。この結論は「削除が不可逆である」ことに強く依存しています。将来ゴミ箱への移動や退避ディレクトリを導入して削除を巻き戻せるようにしたなら、(b) を再検討する余地が出てきます。そのときはこの判断を見直してください。
