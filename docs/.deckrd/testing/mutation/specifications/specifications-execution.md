## 1. Overview

### 1.1 Purpose

変異体を元ソースに触れずに実行し、テストの結果から判定し、実行の前後で作業ツリーを安全な状態に保つ規則を定義する。
対象は変異体の書き出し・テストの実行・5 種の判定・失敗時の継続・後始末・起動時の残骸掃除・drift 検査・ベースライン・同時起動の拒否・SIGINT の扱いである。

### 1.2 Scope

This specification defines the **behavioral rules** and
**classification semantics** of mutation testing harness (execution).

Implementation details are explicitly out of scope.

担当する FR: REQ-F-003, REQ-F-004, REQ-F-005, REQ-F-006, REQ-F-007, REQ-F-008, REQ-F-016, REQ-F-017。
あわせて API DECISIONS の SIGINT の扱いと、残ったロックの扱い (引き継がず中止する) を定める。
変異体の生成・対象解決・許容リスト・レポート・CLI は他ファイルの責務であり、本ファイルは入出力の境界だけを参照する。

## 2. Design Principles

### 2.1 Classification Philosophy

- **元ソースは読むだけ**: 書き込みは変異体ファイルと一時設定に限る。書き換えて戻す操作は一切持たない (REQ-F-003, REQ-NF-001)。
- **判定は「何が検出したか」を正確に表す**: テストが検出したものだけを killed とし、型検査が落としたものは compile-error に分ける (DR-02)。
- **変異体単位の失敗は記録して続行し、監査単位の失敗は中止する**: 1 件の環境要因で全体を止めない一方、ベースライン・ロック・drift のように監査そのものが成立しない状況は終了コードに反映させる。
- **後始末は例外経路でも保証し、保証できない場合は黙らない**: 削除できなかった残骸は列挙して警告し、次回起動の掃除に委ねる。
- **書き込みと削除はロックの内側に限る**: ロックを持たない実行は、何も作らず何も消さない (DR-09)。

### 2.2 Design Assumptions

- `deno test` は既定でテストを同一プロセス内で実行するため、終了させる対象は直接の子プロセスである。テスト自身が起こしたサブプロセスの後始末はテストの責務とする。
- 対象ソースはテストから import で読まれる。ソースを文字列として読むテストには差し替えが効かない (DR-01)。
- 変異体は 1 件ずつ逐次に実行する。テストプロセス自体が並列実行するため、外側で並列化すると timeout の誤判定を招く (DR-05)。
- 動作確認済みの Deno は 2.9.7。型検査の失敗は ANSI 付きの `error: Type checking failed.` として出力される。

```text
+-------------+     +--------------+     +--------------+
| Run Safety  | --> |   Baseline   | --> |  Sequential  |

+-------------+     +--------------+            |

      |                       +----------+  +-----------+  +--------------+
```

### 2.7 DD to DR Promotion Criteria

> **Purpose**: Guidelines for determining when a DD should be promoted to a formal DR.
> Promotion is a **human judgment** — these criteria inform, not automate.

**Consider promoting a DD when:**

1. Cross-specification Impact — The decision affects multiple specifications or modules
2. Architectural Significance — The decision constrains future design choices
3. Non-trivial Alternatives — Multiple viable options existed
4. Stakeholder Visibility Required — The decision should be reviewable by external parties

**Keep as DD when:**

- Decision is local to this specification only
- No significant alternatives existed
- Rationale is self-evident from context

> **Action**: To promote, run `/deckrd dr --add` with the DD context,
> then update DD Status to `Promoted → DR-xx`.

## 3. Behavioral Specification

### 3.1 Input Domain

- Input Type: 変異体の列 (ファイル・行・桁・オペレータ・置換前後の字句・行テキストを持つ)、元の deno 設定、テストの起動引数、1 回のテスト実行あたりの制限時間 (ベースラインと各変異体に共通)、対象ソースファイルの集合、テストプロセスの起動を担う注入可能な提供元、中断を知らせる信号
- Assumptions:
  - 変異体の列は生成側で決定的な順序に並んでいる。
  - 対象ソースファイルはいずれも存在し、読み取れる。
  - 制限時間は正の値である (CLI 側で検証済み)。
  - 変異体の置換前の字句は、指定された行・桁に実在することを前提とするが、ステージング時に確認する (DD-09)。

### 3.2 Output Semantics

- Output Meaning: 変異体ごとの判定の列、drift したファイルの一覧、後始末で削除できなかった残骸の一覧、および実行が中断されたか・ベースラインで中止されたかの区別
- Possible Outcomes:
  - 変異体の判定は `killed` / `survived` / `timeout` / `error` / `compile-error` のいずれか 1 つ
  - 全変異体を処理した完了
  - SIGINT による途中までの結果 (未実行の変異体は判定に含めない)
  - ロック取得失敗・ベースライン失敗による中止 (変異体の判定は 0 件)

| R-226   |   13 | 削除に失敗したファイルがある                                                                                                                                                  | 残骸として列挙し、警告を出す。終了コードは変えず、次回起動時の掃除 (R-205) に委ねる (DD-05)                                        |

R-220〜R-224 は結果の種類 (終了 / timeout / error) による分岐であり、判定は終了コードと出力のみから決まる純粋な規則でなければならない。

### 4.3 SIGINT

| Rule ID | Step | Condition           | Outcome                                                                                                                                                                                                                                                                                                        |
| ------- | ---: | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-227   |    1 | SIGINT を受け取った | 実行中のテストプロセスがあれば終了させ、新しい変異体を開始しない。実行中だった変異体の判定は記録せず、後始末 (R-225) を行う。ハッシュの記録 (R-206) が終わる前に受け取った場合は、進行中の掃除・ハッシュ記録を終えてから drift 検査を省き、中断の事実だけをレポートしてロックを解放し、終了コード 130 で終わる |
| R-228   |    2 | 後始末が終わった    | drift 検査 (R-212) を行い、そこまでに判定した結果でレポートを出し、ロック解放 (R-213) を行って終了コード 130 で終わる。追加の SIGINT で後始末を省略しない (DD-08)                                                                                                                                              |

No reordering is permitted.
