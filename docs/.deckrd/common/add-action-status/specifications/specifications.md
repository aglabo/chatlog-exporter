## 1. Overview

### 1.1 Purpose

全 skill 横断で利用できる汎用アクション・ステータス型の仕様を定義する。
パイプライン処理における「実行予定の操作」と「実行結果の状態」を統一的な値セットで表現し、
チャットログエントリにこれらを付与するラッパー型の振る舞いを規定する。

### 1.2 Scope

この仕様書は、アクション値セット・ステータス値セット・ラッパー型の**振る舞い規則**を定義する。
実装の詳細（型シグネチャ・ファイル構成）は明示的にスコープ外とする。

## 2. Design Principles

### 2.1 Classification Philosophy

- **アクション（Action）**: パイプラインが次に実行する操作を表す。設定されていない場合は「未決定」を意味する。
- **ステータス（Status）**: パイプラインが実行した操作の結果を表す。設定されていない場合は「未処理」を意味する。
- アクションとステータスは独立した値セットであり、一方の値が他方を決定しない。
- 「未処理」を表す特殊値（pending 等）は持たない。未処理はアクション・ステータスが未設定であることで表現する。

### 2.2 Design Assumptions

- ラッパー型は既存のチャットログエントリ型を変更せず、参照として保持する（Phase 1）。
- `filePath` は `ActionStatusOptions` に集約し、チャットログエントリ型の `options.filePath` との二重管理は Phase 2 で解消する。
- 各 skill は共通値セットを使用しつつ、skill 固有の拡張値を別途定義できる。
- アクション・ステータスの値セットは閉じた列挙であり、値の追加は定数テーブルの変更のみで行う。
- テスト時に `filePath` が不要な場合は空文字列 `''` を使用する（必須フィールドだが空値を許容）。

## 3. Behavioral Specification

### 3.1 アクション値セットの振る舞い

アクション値セットは、パイプラインが実行予定の操作を表す閉じた列挙である。

| 値       | 意味                                           | 使用フェーズ         |
| -------- | ---------------------------------------------- | -------------------- |
| `keep`   | チャットログファイルをそのまま保持する         | 判定フェーズ後       |
| `skip`   | このエントリの処理をスキップする               | 事前フィルタフェーズ |
| `move`   | チャットログファイルを別ディレクトリへ移動する | 判定フェーズ後       |
| `remove` | チャットログファイルを削除する                 | 判定フェーズ後       |
| `write`  | チャットログファイルに内容を書き込む           | 変換フェーズ後       |

アクション値セットの値は相互排他的である。1つのエントリに同時に複数のアクションを設定することはできない。

<!-- impl-note: ENTRY_ACTIONS as const オブジェクト + EntryAction = typeof ENTRY_ACTIONS[keyof typeof ENTRY_ACTIONS] -->

### 3.2 ステータス値セットの振る舞い

ステータス値セットは、パイプラインが実行した操作の結果を表す閉じた列挙である。

| 値            | 意味                                       | 対応するアクション         |
| ------------- | ------------------------------------------ | -------------------------- |
| `pre-skipped` | 事前フィルタによって除外された             | `skip`（事前フィルタ起因） |
| `skipped`     | 処理をスキップした                         | `skip`                     |
| `kept`        | ファイルを保持した（削除・移動しなかった） | `keep`                     |
| `moved`       | ファイルを移動した                         | `move`                     |
| `removed`     | ファイルを削除した                         | `remove`                   |
| `written`     | ファイルへの書き込みが完了した             | `write`                    |
| `error`       | 処理中にエラーが発生した                   | 任意（エラー時に設定）     |

`error` ステータスは任意のアクション後に設定できる。他のステータス値とエラーは排他的である。

<!-- impl-note: ENTRY_STATUSES as const オブジェクト + EntryStatus = typeof ENTRY_STATUSES[keyof typeof ENTRY_STATUSES] -->

### 3.3 ラッパー型の振る舞い

ラッパー型はチャットログエントリとオプション情報を保持する複合型であり、2つのプロパティのみを持つ。

**`entry` プロパティ（必須）:**

- チャットログエントリの参照（既存エントリ型をそのまま保持し、変更しない）

**`options` プロパティ（必須）:**

- ファイルパス（必須。テスト時は空文字列 `''` で対応）
- アクション（オプション。未設定の場合は「未決定」を意味する）
- ステータス（オプション。未設定の場合は「未処理」を意味する）
- 理由（オプション。エラーや除外が発生したときの詳細メッセージ。`error`・`pre-skipped`・`skipped` ステータス時に推奨）

`filePath` はチャットログエントリ型の `options.filePath` と Phase 1 では並行して存在するが、
Phase 2（全 skill 移行完了後）にチャットログエントリ型側の `options` を削除することで一本化される。

## 4. Decision Rules

評価はこの順序に従う。

| Rule ID | Step | 条件                                                                                                         | 結果                             |
| ------- | ---: | ------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| R-001   |    1 | アクション値として `keep`・`skip`・`move`・`remove`・`write` 以外が設定された                                | 不正な値として型エラー           |
| R-002   |    2 | ステータス値として `pre-skipped`・`skipped`・`kept`・`moved`・`removed`・`written`・`error` 以外が設定された | 不正な値として型エラー           |
| R-003   |    3 | アクション・ステータスが未設定の状態でラッパー型が生成された                                                 | 正常（未決定・未処理として扱う） |
| R-004   |    4 | チャットログエントリ以外の型がエントリフィールドに設定された                                                 | 不正な値として型エラー           |
| R-005   |    5 | `error` ステータスのエントリで理由フィールドが未設定                                                         | 許可（推奨だが必須ではない）     |
| R-006   |    6 | `options.filePath` に空文字列 `''` が設定された                                                              | 正常（テスト用途として許容）     |

順序の変更は不可。

## 5. Edge Cases

| 入力状態                                           | 振る舞い                               | REQ                  | 根拠                                           |
| -------------------------------------------------- | -------------------------------------- | -------------------- | ---------------------------------------------- |
| アクション・ステータスともに未設定でラッパー型生成 | 正常に生成される（未決定・未処理状態） | REQ-F-003            | DD-03: pending 値なし、未設定で未処理を表現    |
| アクション設定済み・ステータス未設定               | 正常（操作は決定済みだが未実行）       | REQ-F-003            | パイプライン前半フェーズの通常状態             |
| ステータスが `error` で理由フィールドが未設定      | 許可（エラー詳細なし）                 | REQ-F-003            | 理由フィールドはオプション                     |
| アクション・ステータスに列挙外の文字列を設定       | 型エラー（コンパイル時に検出）         | REQ-F-001, REQ-F-002 | DD-02: as const パターンにより閉じた列挙を保証 |
| 同一エントリに複数アクションを設定                 | 不可（型として単一値のみ）             | REQ-F-001            | アクション値セットは相互排他的                 |
| `options.filePath` が空文字列 `''`                 | 正常に生成される                       | REQ-F-003            | DD-07: テスト用途として空文字列を許容          |
