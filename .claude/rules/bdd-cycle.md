# BDD 開発サイクル（chatlog-exporter 固有）

RGR サイクルの適用トリガー・免除条件・フェーズゲート、および `bdd-coder` への委譲ルールは
deckrd の `deckrd-rule-bdd-cycle.md` が正とする
（`.claude/rules/deckrd-rules/deckrd-rules-index.md` 参照）。
本ファイルは chatlog-exporter 固有の差分のみを定める。

テストコードを書くときは `docs/rules/testing-conventions.md` を Read する。

## 委譲後の差分検証

委譲直後に、実際に変更されたファイルを差分で確認する。

```bash
git --no-optional-locks status --short
git --no-optional-locks diff --stat HEAD -- <対象ディレクトリ>
```

`--no-optional-locks` は必須。rtk 経由の `git status` はキャッシュした古い出力を返すことが
あるため、これを付けるか `ls` でファイルを直接確認する。

## レビュー指摘もテスト先行

コードレビューが欠陥を指摘したとき、実装をすぐ直さない。
**先に検出テストを追加して RED を確認し、それから実装を修正する。**

- 委譲は RED 専用と GREEN 専用の 2 回に分ける。RED 側には「実装を変更してはならない。
  テストが失敗したまま終わるのが成功条件」と明記する。GREEN 側には失敗中のテスト ID と失敗内容を渡す
- 既存実装で初回から通るテストは、実装を一時的に変異させて落ちることを確認させる（空振りテストの排除）
- 対象ファイルが git 未追跡だと `git diff HEAD -- <path>` は内容が変わっていても空を返す。
  変異の revert 検証には md5 かバックアップとの diff を使わせる

根拠: 2026-09-13 の T-09（llama バックエンドの契約検証）でレビューが 4 回 BLOCKED を出した。
欠陥はいずれも「検証を通過したあとで値が黙って落ちる」形で、テストが全件緑でも見えなかった。
実際 2 回目の修正は「応答のキー順依存」を「契約定義の記述順依存」へ移しただけで、
3 回目のレビューで再び BLOCKED になった。テストを先に書くと、指摘が実在すること・修正がその欠陥を
塞ぐこと・修正が依存先を移しただけでないことの 3 つが同時に固定される。

## 新規モジュールは production から呼ばれているか確認する

モジュールを追加したら、**production 側の import を grep で確認する。**
unit テストが全部 green でも「production から呼ばれているか」は検証されない。
コミット前に `deno task test:module all <mod>` を通す（型検査が落ちるとそのモジュールの
テストが 1 件も実行されないまま緑に見える）。

根拠: filter/strip の Commit 10 で `recoverOrphans` が実装・unit テスト済みなのに呼び出し元が
1 つも無い状態でコミットされ（`5d248a20`）、`--recover-orphans` が復旧対象を書き換える実害バグになった。

## 「1 委譲 = 1 タスク」の根拠

2026-08-18 の cle-vyt で、T-01（新規ファイル作成のみ）を委譲したエージェントに
T-01 と T-02 が併記されたチェックリストを渡したところ、プロンプトで「T-01 のみ」と
指示したにもかかわらず T-02 相当まで実装された。さらに最終報告では
「`write-stripped.ts` は触っていない」と申告した。

つまり、**渡す資料に他タスクが載っていれば指示は無視され、自己申告と実差分は食い違う**。
チェックリストを渡す場合は当該タスク分のみを記載したファイルにする。
想定外のファイルが変更されていたら、次を委譲せず、まずユーザーに報告する。
