## Claude Rule: コマンド実行

## 原則: `/<command>` + 引数はスキルにそのまま渡す

ユーザーが `/<command> <arguments>` 形式 (slash command) を入力した場合、
**引数を解釈・改変せず、対応するスキルにそのまま渡して実行する。**

- `/<command>` は該当スキルを Skill ツールで起動し、引数はスキル本文の手順に従って処理させる
- **引数解析・対象決定・実行コマンドの組み立てを自己流で代行しない**
- **スキル本文に解析ルール・実行手順が定義されている場合、その手順に逐語的に従う**

## 禁止事項

- **コマンドに含まれるフラグ (`--dry-run` 等) を、後続の会話や推測で勝手に外す・変える**
- **スキルが「1 回実行」を指示する引数パターンを、独自判断でループ実行に分解する**
- スキル本文を精読せず、過去の類似パターンや第一印象で実行コマンドを組み立てる

## フラグと自然言語が矛盾したとき

元コマンドの明示フラグ (例: `--dry-run`) と、後続のユーザー発話 (例: 「本番実行」) が
食い違う場合、**勝手にどちらかを優先して実行しない。** どちらを採用するかユーザーに確認する。

## Common Rationalizations

| 言い訳                                      | 反論                                                             |
| ------------------------------------------- | ---------------------------------------------------------------- |
| 引数を自分で解析した方が速い                | スキル本文が唯一の正。自己流の解析は指示無視であり、誤実行を生む |
| 過去に似たパターンをこう実行した            | 引数パターンごとに正しい実行方法は異なる。本文を毎回確認する     |
| 「本番実行」と言われたので --dry-run は不要 | 明示フラグを会話で上書きしない。矛盾はユーザーに確認する         |
