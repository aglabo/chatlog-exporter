# コーディング規約（プロジェクト固有）

## コード調査ツール（MCP）

コードを書く・編集する前に、以下の MCP ツールで既存実装を調査する。

| ツール           | 用途                                           |
| ---------------- | ---------------------------------------------- |
| `codegraph`      | シンボル検索・呼び出し関係・影響範囲の把握     |
| `cocoindex-code` | 意味ベースのコード検索（キーワード不明時）     |
| `serena`         | ファイル・シンボル操作、プロジェクト全体の概観 |

- まず `codegraph_context` / `codegraph_search` で対象シンボルを特定する
- `cocoindex-code` は exact match が難しい概念検索に使う
- 既存の実装・パターンを確認してから新規コードを書く

## ライブラリ優先順序（このプロジェクト）

1. **共通ライブラリ**（`skills/_scripts/libs/`）— プロジェクト共通のユーティリティ関数・クラス
2. **モジュール専用ライブラリ**（`skills/<module>/scripts/`）— 対象モジュール内の既存実装
3. **外部モジュール**（JSR: `@std/*` 等）— Deno 標準ライブラリや登録済み依存

## エラーハンドリング（このプロジェクト）

- 回復不可能な異常は `ChatlogError` を throw する（汎用例外ではなく必ず `ChatlogError`）
  - 例：辞書ファイルが存在しない → `{ misc: {} }` を返さず `ChatlogError('FileDirNotFound')` を throw
- 許容例：空の YAML（定義なしとして扱う）、オプショナルな設定ファイルの省略
