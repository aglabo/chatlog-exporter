## Overview

`/set-frontmatter` has the AI read each chat log and generate its metadata: a `title`, the log `type`,
a `category`, `topics`, and `tags`. The category, topics, and tags are chosen from the dictionaries in
`.config/chatlog-exporter/dics/`, so the vocabulary stays consistent across all your logs.
After generating the metadata, the AI reviews it once more to correct its choices.

It is the last step of the [basic workflow](../user-guide/basic-workflow), run after
[`/classify-chatlogs`](./classify-chatlogs). The files it writes can be imported into an Obsidian vault as they are.

It calls the AI several times per file, so it is the most token-intensive skill.
Use `--no-review` to skip the review and finish faster.

## Usage

```bash
/set-frontmatter [agent] [YYYY-MM] [options]
/set-frontmatter <input-path> [output-path] [options]
```

### Arguments

| Argument      | Description                                                                                |
| ------------- | ------------------------------------------------------------------------------------------ |
| `agent`       | `claude`, `codex`, or `chatgpt`. Defaults to `agent` in `config.yaml` (`claude` if unset). |
| `YYYY-MM`     | The month to process. Omit it to process all periods. It must follow `agent`.              |
| `input-path`  | A directory to process instead of `agent` / `YYYY-MM`. It must contain a `/`.              |
| `output-path` | A directory to write to. Optional; it must contain a `/`.                                  |

There is no argument for a project. To process a single project, pass its directory as `input-path`.

### Options

| Option             | Description                                                                             |
| ------------------ | --------------------------------------------------------------------------------------- |
| `--no-review`      | Skip the AI review of the generated metadata.                                           |
| `--input-dir DIR`  | Directory to process, the same as giving `input-path`.                                  |
| `--output-dir DIR` | Directory to write to, the same as giving `output-path`.                                |
| `--dics DIR`       | Use a different dictionary directory.                                                   |
| `--prompts DIR`    | Use a different prompt directory.                                                       |
| `--concurrency N`  | Number of files processed in parallel. Default 4.                                       |
| `--model MODEL`    | AI model to use. Defaults to `model` in `config.yaml`. See [`--model`](./model-option). |
| `--debug`          | Print AI diagnostic logs, including part of the responses, to stderr.                   |
| `--config FILE`    | Use a different `config.yaml`.                                                          |
| `--dry-run`        | Write nothing. The AI is not called, so it only shows the state of each file.           |

The directory options must contain a `/` (`./dics` works, `dics` does not).

:::warning
The run stops before calling the AI if `category.dic` or `types.dic` is missing or empty, or if they lack
the fallback values (`development` in `category.dic`, `research` in `types.dic`).
Keep those entries when you edit the dictionaries.
:::

## Input and output

By default it reads `chatlogs/normalizeLogs/<agent>/<YYYY>/<YYYY-MM>/`, including the project subdirectories,
and writes to the same path under `chatlogs/outputLogs/`. The source files are left as they are.

<FileTree>

- chatlogs/
  - normalizeLogs/
    - claude/
      - 2026/
        - 2026-06/
          - chatlog-exporter/
            - 2026-06-12-fix-encoding-a1b2c3d4e5f6-01-3f9a2c1.md
  - outputLogs/
    - claude/
      - 2026/
        - 2026-06/
          - chatlog-exporter/
            - 2026-06-12-fix-encoding-a1b2c3d4e5f6-01-3f9a2c1.md

</FileTree>

When the input is a month directory under `normalizeLogs/` (`.../normalizeLogs/.../<YYYY>/<YYYY-MM>`), the output
always goes to the matching path under `outputLogs/`, and `output-path` is ignored.

The frontmatter is written with these fields, in this order. Any other field is removed:

```yaml
---
title: Fix encoding of exported logs   # generated by the AI
date: 2026-06-12                       # kept from the source
type: incident                         # execution / incident / discussion / research / writing
category: development                  # from category.dic
session_id: a1b2c3d4-...               # kept from the source
project: chatlog-exporter              # kept from the source
slug: fix-encoding                     # kept from the source
topics:                                # from topics.dic
  - development
  - testing
tags:                                  # from tags.dic
  - lang/typescript
---
```

Files already written are skipped on a re-run, so you can resume an interrupted run by running it again.

## Examples

Add frontmatter to the Claude logs of June 2026:

```bash
/set-frontmatter claude 2026-06
```

Do the same without the AI review, to finish faster:

```bash
/set-frontmatter claude 2026-06 --no-review
```

When it finishes, the skill reports the counts of files found, written, failed, skipped, and already written.
The contents of `chatlogs/outputLogs/` are now ready to import into Obsidian.
