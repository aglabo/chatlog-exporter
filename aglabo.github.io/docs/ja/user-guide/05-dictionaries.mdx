## 概要

`.config/chatlog-exporter/dics/` の辞書は、AI が選んでよい語彙を定めます。
次の 2 つのスキルが辞書を前提にしています。

- **classify-chatlogs** は `projects.dic` を前提とします。AI は、ここに定義された名前の中からだけ各ログのプロジェクトを選びます。
- **set-frontmatter** は `dics/` 配下の辞書を前提とします。`type`・`category`・`topics`・`tags` を辞書から選びます。

AI が決まったリストから選ぶため、すべてのログで語彙が揃います。
自分のプロジェクトや関心に合わせて辞書を編集してください。

## 辞書の一覧

| ファイル         | 使うスキル        | 読み込むタイミング    | 定めるもの                                                   |
| ---------------- | ----------------- | --------------------- | ------------------------------------------------------------ |
| `projects.dic`   | classify-chatlogs | 起動時 (分類の前)     | プロジェクト名。名前がそのまま出力先のサブディレクトリになる |
| `types.dic`      | set-frontmatter   | 起動時 (全辞書を一括) | `type` の値 (ログの種別)                                     |
| `category.dic`   | set-frontmatter   | 起動時                | `category` の値 (ログの領域)                                 |
| `topics.dic`     | set-frontmatter   | 起動時                | `topics` の値 (domain + aspect)                              |
| `tags.dic`       | set-frontmatter   | 起動時                | `tags` の値                                                  |
| `namespaces.dic` | (なし)            | 読み込まれない        | タグのネームスペース (`tags.dic` のキーの左側)               |

ディレクトリは `config.yaml` の `dicsDir` (プロジェクト辞書は `projectsDic`)、
または set-frontmatter の `--dics` で変更できます。[config.yaml のカスタマイズ](./configuration) を参照してください。

## 書式

辞書はすべて YAML です。トップレベルのキー 1 つが 1 エントリで、キーがそのまま AI の出力する値になります。

```yaml
<key>:
  def: <キーを端的に定義する短文。AI が判断に使う>
  desc: <人間向けの説明>
  rules:
    when:
      - <このキーを選ぶ状況>
    not:
      - <選ばない状況 (代わりに何を選ぶか)>
```

| フィールド | 意味                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| `def`      | キーの短い定義。AI が判断に使う主な文。英語で書きます。                                                         |
| `desc`     | 人間向けの説明。                                                                                                |
| `rules`    | 境界ケースの判断補助: `when` (当てはまる)・`not` (当てはまらない)。辞書によっては `while`・`where` も使います。 |

`#` で始まる行はコメントです。配布版の各辞書の冒頭コメントに設計方針と選定ルールが書かれているので、編集前に読んでください。

## projects.dic

`projects.dic` は分類精度に最も大きく影響します。
AI がログの所属プロジェクトを決めるときに見るのは、このファイルの情報だけです。

### AI に渡る情報

classify-chatlogs は、各プロジェクトについて **キー**・**`def`**・**`rules.when` / `rules.not`** を AI に渡します。
`desc`・`category`・`rules.while`・`rules.where` は **渡されない**ため、結果に影響しません。
各ログについては frontmatter の title・category・topics・tags を渡します
(メタデータが無いログは本文の先頭 500 文字)。

### プロジェクトを追加する

プロジェクト名をキーにしてエントリを追加します。たとえば、自作のメモアプリ `memo-pad` のログを分類したい場合は次のように書きます。

```yaml
memo-pad:
  def: A personal note-taking web app built with Deno and Fresh
  category: development
  desc: 自作のメモアプリ。Deno + Fresh で開発している
  rules:
    when:
      - memo-pad のコード・UI・データ保存に関するログ
      - Fresh のルーティングや island を memo-pad 向けに実装したログ
    not:
      - Fresh や Deno の一般的な使い方の調査で、memo-pad に触れていないもの（misc で分類）
```

分類精度を上げるコツ:

- **`def` を具体的に書く。** 技術・製品・目的を挙げ、AI がプロジェクトを見分けられるようにします。
- **`when` にはプロジェクトを特定できる手がかりを書く。** コマンド名・ファイル名・リポジトリ名・固有の用語などです。
- **`not` には紛らわしいケースを書き**、代わりに選ぶプロジェクトを添えます (`（… で分類）`)。
  2 つのプロジェクトが重なる場合は、両方に `not` を書きます。
- **キーはディレクトリ名になります。** `/`・`\`・`:` を含めず、`.` や `..` にしないでください。
  配布版と同じく、小文字とハイフンを使います。

### misc

`misc` は、どのプロジェクトにも当てはまらないログの受け皿です。
`projects.dic` に `misc` が無ければ自動で追加されます。
プロジェクトが 1 つも定義されていない場合は、すべてのログが `misc` になり、警告が出ます。
`projects.dic` が存在しない場合、classify-chatlogs はエラーで停止します。

その他の分類の挙動 (frontmatter の `project:` の優先、短いログ、キャッシュ) は
[`/classify-chatlogs` リファレンス](../reference/classify-chatlogs) を参照してください。

## set-frontmatter の辞書

set-frontmatter は辞書をプロンプトに埋め込んで AI に渡します。
`types.dic`・`category.dic`・`topics.dic` はキー・`def`・`desc`・すべての `rules` を渡します。
`tags.dic` は **キーだけ** をカンマ区切りで渡します。

### types.dic

`type` を定めます。配布版は `execution`・`incident`・`discussion`・`research`・`writing` の 5 種別です。
AI は種別を**書かれている順に**確認し、最初に当てはまったものを選ぶため、エントリの順序に意味があります。

- `research` は必須です。AI が辞書に無い値を返したときの代替値として使います。
- ファイルが無い、または空の場合、set-frontmatter は起動時に停止します。

### category.dic

`category` (ログの大きな領域。1 ログに 1 つ) を定めます。
配布版は `development`・`infrastructure`・`tooling`・`ai`・`writing`・`knowledge`・`creative`・`casual` です。

- `development` は必須です。不正なカテゴリーの代替値として使います。
- ファイルが無い、または空の場合、set-frontmatter は起動時に停止します。

### topics.dic

`topics` を定めます。1 ログに **domain** を 1 つと **aspect** を 0〜2 個付けます。

- domain のエントリは **`category.dic` と同じキー**にします。domain には常にログの category が入ります。
  カテゴリーを追加・改名・削除したら、`topics.dic` も同じように変更してください。
- aspect のエントリ (`learning`・`decision`・`architecture`・`validation` など) はログの観点を表します。
  グループごとの制約 (同じグループから 1 つまで) は、ファイル冒頭のコメントと `meta.yaml` プロンプトに書かれています。

### tags.dic

`tags` を定めます。キーは `<namespace>/<value>` の形で書きます (例: `ai/claude`・`lang/typescript`)。

- **キーの左側 (`/` の前) がネームスペースです。** キーの一部として AI に渡り、そのタグが何の観点を記録するかを伝えます
  (`ai/` は AI モデル、`lang/` は言語、`tool/` はツールなど)。
- AI に渡るのはキーだけなので、**キー自体で意味が伝わる**ようにします。
  `def`・`desc`・`rules`・`namespace:` フィールドは人間向けのメモで、AI には渡りません。
- 実際に使っているツール・言語・環境のタグを追加します。すべてのログに付くようなタグは情報を持たないので避けます。

### namespaces.dic

`tags.dic` のキーの左側に使うネームスペース (`ai`・`lang`・`tool`・`os` など) と、それぞれを使う場面を定めます。
タグを追加するときは、ここに定義されたネームスペースを使います。

ファイル自体はどのスキルも読み込みません。ネームスペースは `tags.dic` のキーを通じて効きます。
新しいネームスペースを追加したときは、ネームスペースの一覧が 1 か所にまとまるよう、ここにも追加してください。

## 編集した後

- 変更は次回の実行から反映されます。ビルドなどは不要です。
- classify-chatlogs はファイルごとに結果をキャッシュするため、分類済みのログはプロジェクトを維持します。
  キャッシュ上のプロジェクトが `projects.dic` から削除された場合に限り、破棄して分類し直します。
  新しい辞書ですべて分類し直す場合は、`cacheDir` 配下の `classify-cache/` を削除してください。
- YAML の構文エラーがあるとスキルは停止します。編集後はインデントを確認してください。
- 効果は、まず少数のログで試して確認します。set-frontmatter の `--dry-run` は AI を呼ばないため、確認できるのは処理対象のファイルで、選ばれる値ではありません。

:::warning
`/setup-chatlogs --force` は辞書を配布版で置き換えます。実行前に控えを取るか、コミットしておいてください。
:::
