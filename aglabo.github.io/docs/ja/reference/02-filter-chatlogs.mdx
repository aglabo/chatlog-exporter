## 概要

`/filter-chatlogs` は、各チャットログを KEEP / DISCARD に判定し、DISCARD のものを**削除**します。
最初の引数で選ぶ 3 つのモードがあります。

| モード         | 内容                                                                                  | AI 使用 |
| -------------- | ------------------------------------------------------------------------------------- | ------- |
| `noise-filter` | 極端に短いログや Git 操作だけのログなど、決まったノイズのパターンに一致するログを削除 | なし    |
| `filter`       | 判断の理由が残っているかを AI に判定させ、残っていないログを削除                      | あり    |
| `strip`        | 本文先頭の定型部 (`TOPICS ASSIGNMENT RULES` など) を除去                              | なし    |

モードを省略すると `filter` になります。

[基本ワークフロー](../user-guide/basic-workflow) では 2 回実行します。1 回目はエクスポートしたセッションに、
2 回目は [`/normalize-chatlogs`](./normalize-chatlogs) が分割したセグメントに対して実行します。
先に `noise-filter`、後に `filter` を実行すると、安価なパターン判定を通過したログだけを AI が読むことになります。

AI フィルタが残すのは、決定とその根拠、却下された案とその理由、発見された制約、ハマりどころと解法、ユーザーの確定回答を含むログです。
実行ステータスのみ、些末な Q&A、現在のコードから自明な結論、そのセッション内でしか意味を持たない記述だけのログは削除します。

## 使い方

```bash
/filter-chatlogs [noise-filter|filter] [agent] [YYYY-MM] [オプション]
/filter-chatlogs [noise-filter|filter] <path> [オプション]
/filter-chatlogs strip <agent> <YYYY-MM> [オプション]
/filter-chatlogs strip <path> [オプション]
```

### 引数

| 引数      | 説明                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------ |
| `agent`   | `claude`、`codex`、`chatgpt`。省略時は `config.yaml` の `agent` (未設定なら `claude`)。                |
| `YYYY-MM` | 処理する月。省略すると全期間が対象です。`strip` では、path を指定しない限り必須です。                  |
| `path`    | `agent` / `YYYY-MM` の代わりに処理するディレクトリ。`/` を含む必要があります。2 回目の実行で使います。 |

path を指定しない場合の対象は `chatlogs/originalLogs/<agent>/<YYYY>/<YYYY-MM>/` です。

### オプション

| オプション           | モード   | 説明                                                                                               |
| -------------------- | -------- | -------------------------------------------------------------------------------------------------- |
| `--dry-run`          | すべて   | 削除・書き換えを行いません。モードごとの報告内容は下記の注意を参照してください。                   |
| `--single-file`      | `filter` | 1 回の AI 呼び出しで 1 ファイルずつ判定します。                                                    |
| `--chunk-size N`     | `filter` | 1 回の AI 呼び出しにまとめるファイル数 (1〜10)。既定は `config.yaml` の `chunkSize` (配布版は 2)。 |
| `--max-body-chars N` | `filter` | AI に渡す本文 1 本あたりの最大文字数 (1〜100000)。既定は 8000。                                    |
| `--model MODEL`      | `filter` | 使用する AI モデル。既定は `config.yaml` の `model`。書き方は [`--model`](./model-option) を参照。 |
| `--debug`            | `filter` | AI の診断ログ (応答本文の一部を含む) を stderr に出力します。                                      |
| `--recover-orphans`  | `strip`  | 中断した実行が `.bak` として残した元ファイルを復帰させ、strip は行わずに終了します。               |

:::warning
**`--dry-run` で分かることはモードごとに異なります**

- `filter`: AI を呼び出さないため、KEEP / DISCARD の判定は行われません (`judged=0`)。
  判定対象になるファイルの一覧を表示するだけです。
- `noise-filter`: 通常実行と同じ規則で判定するため、結果の事前確認に使えます。
  削除されるはずのファイルは `skip` に計上され、`remove` は常に 0 になります。
  `skip` を「実行すれば削除される件数」として読んでください。
- `strip`: 全ファイルを通常実行と同じく判定します。書き換えられるはずのファイルは `skipped` に計上され、
  `stripped` は常に 0 になります。

:::

:::note
`filter` モードでは、確信度の低い DISCARD (`config.yaml` の `discardThreshold` 未満、既定 0.7) は削除されず、
次回の実行で再判定されます。判定結果はキャッシュされるため、再実行時に判定済みのファイルで AI を呼び出すことはありません。
:::

## 入力と出力

どのモードも対象ディレクトリをその場で処理します。別の出力ディレクトリはありません。

| モード         | 読み込むもの                          | 書き込むもの                                   |
| -------------- | ------------------------------------- | ---------------------------------------------- |
| `noise-filter` | 対象ディレクトリの `.md` ファイル     | ノイズと判定したファイルを削除                 |
| `filter`       | 対象ディレクトリの `.md` ファイル     | DISCARD と判定したファイルを削除               |
| `strip`        | 対象ディレクトリ配下の `.md` (再帰的) | 定型部のあるファイルを書き換え。他は変更しない |

`strip` は書き換えの間、元ファイルを `.bak` として退避し、エラーなく完了すると対象ディレクトリ配下の `.bak` をすべて削除します。
対象ディレクトリ配下には、自分で作った `.bak` ファイルを置かないでください。

:::warning
このスキルはファイルを削除します。先に `--dry-run` 付きで実行して対象を確認してから、本番の実行を行ってください。
:::

## 実行例

1 回目: エクスポートした 2026 年 6 月分のセッションに対して実行します。

```bash
/filter-chatlogs noise-filter claude 2026-06 --dry-run
/filter-chatlogs noise-filter claude 2026-06
/filter-chatlogs filter claude 2026-06
```

2 回目: `/normalize-chatlogs` が分割したセグメントに対して実行します。
`claude 2026-06` の形式では再び `originalLogs` を指すため、パスで指定します。

```bash
/filter-chatlogs noise-filter "chatlogs/normalizeLogs/claude/2026/2026-06"
/filter-chatlogs filter "chatlogs/normalizeLogs/claude/2026/2026-06"
```

完了すると、残した・スキップした・削除した・エラーになったファイルの件数が報告されます。
